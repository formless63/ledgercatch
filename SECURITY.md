# Security reports

Use the repository's private vulnerability reporting feature once the public repository is configured. Do not open public issues containing credentials, real captures, invoices or exploitation details. If private reporting is not enabled, request a private reporting channel without disclosing the vulnerability publicly.

Self-hosting operators control authentication allowlists, HTTPS, backups, storage credentials, external endpoints and update policy. Keep the application and worker on the same reviewed release. Never use the synthetic demo to hold real purchases.
